# Performance Assistant

Локальное приложение для исследования производительности: Web-интерфейс, терминальный клиент, HTTP/SSE API и отдельный устойчивый Worker. Python 3.11+, SQLite WAL. Развёртывание рассчитано на одного пользователя и привязано к `127.0.0.1`.

## Запуск

В этой рабочей папке `.venv` уже подготовлено. Запустите в PowerShell:

```powershell
.\start.ps1
```

Откройте [http://127.0.0.1:8765](http://127.0.0.1:8765). Скрипт запускает API и Worker отдельными процессами; Ctrl+C останавливает оба. Закрытие вкладки не останавливает Worker. После остановки процесса работа восстанавливается из очереди после истечения lease (150 секунд).

Установка на другой машине:

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
Copy-Item .env.example .env
.\start.ps1
```

В Linux/macOS используйте `python3 -m venv .venv`, `.venv/bin/python -m pip install -e '.[dev]'`, затем `.venv/bin/python -m performance_assistant serve`. Для секретов вне Windows требуется `PA_MASTER_KEY`, переданный через окружение процесса.

Отдельные команды:

```powershell
.\.venv\Scripts\python.exe -m performance_assistant api
.\.venv\Scripts\python.exe -m performance_assistant worker
.\.venv\Scripts\python.exe -m performance_assistant tui
```

## Настройка MCP через `.env`

Приложение не привязано к выдуманным инструментам конкретного профилировщика. Оператор задаёт реальные имена из его MCP-каталога. Пример ниже иллюстративный, а не контракт существующего сервера:

```dotenv
PA_MCP_URL=https://profiler.example/mcp
PA_MCP_READ_TOOLS=actual_read_tool
PA_MCP_PROFILE_TOOL=actual_read_tool
PA_MCP_PROFILE_ARGUMENT=result_id
PA_MCP_PROFILE_ARGS={}
PA_MCP_PROFILE_IDENTITY_PATH=result.id
```

- Поддерживается MCP Streamable HTTP: JSON и конечный SSE-ответ на POST. Legacy SSE и stdio не реализованы.
- `PA_MCP_READ_TOOLS` — явный список инструментов, которые владелец сервера проверил как read-only. Само обнаружение инструментов разрешения не расширяет.
- `PA_MCP_PROFILE_TOOL` необязателен. Без него диагностика проверяет протокол/каталог, а доступ к профилю остаётся неизвестным. Модель не выбирает инструменты для «озеленения» диагностики.
- Аргумент профиля получает непрозрачный ID результата. Путь к файлу вместо ID не принимается.
- `PA_MCP_PROFILE_ARGS` — фиксированные JSON-аргументы **без секретов**. JSON Schema инструмента проверяется перед вызовом, внешние `$ref` запрещены.
- `PA_MCP_PROFILE_IDENTITY_PATH` — необязательный путь через точки внутри `structuredContent`. Без него результат чтения явно помечен как не имеющий независимой проверки идентичности.
- После изменения `.env` перезапустите оба процесса. Старые запуски сохраняют собственные настройки; диагностика использует текущие.

Токен можно ввести в разделе «Настройки подключения» или задать `PA_MCP_TOKEN` в окружении. Значение импортируется в зашифрованное backend-хранилище. Предпочтителен UI, чтобы не хранить открытый токен в `.env`. Для запросов с токеном необходим HTTPS, перенаправления запрещены.

При использовании UI токен привязывается также к выбранному репозиторию. Токен из окружения — сервисный токен, связанный с MCP-адресом. Подтверждённая смена репозитория в активном запуске снимает привязку токена. Не передавайте секреты через чат, аргументы инструментов, исходники или документацию.

## Модель и документация

```dotenv
PA_MODEL_URL=https://your-provider.example/v1/chat/completions
PA_MODEL_NAME=your-model
PA_MODEL_TOKEN=
PA_MODEL_CONTEXT_TOKENS=16384
PA_DOCUMENT_PATH=C:/docs/profiler.md
```

Адаптер ожидает совместимый Chat Completions JSON-интерфейс с `response_format=json_object`. Выбор модели остаётся за оператором. Без модели доступны ручная подготовка задачи, безопасная маршрутизация основных RU/EN-команд, диагностика, сбор свидетельств и инвентарный отчёт. Экспертная интерпретация не симулируется.

Документация читается целиком из явно настроенного локального UTF-8 файла; ссылки из неё не загружаются. Reference expert получает целый документ, если он помещается в свой контекст. Иначе в отчёте записывается ограничение. Guidance не считается измерением.

## Основной сценарий

1. Напишите `/task Исследуй задержку обработки запросов` или заполните задачу справа.
2. Укажите Profile ID **или** локальный Git-репозиторий. При необходимости задайте ref, файлы, бюджет и открытые вопросы. Сохраните задачу.
3. Для диагностики выберите объекты в независимых настройках подключения и нажмите «Проверить всё» либо используйте `/check profiler`, `/check git`, `/check docs`.
4. Нажмите **Run**. Задача должна иметь описание, цель и не иметь открытых вопросов. Обсуждение само анализ не запускает.
5. Следите за статусом, отвечайте на коррелированные вопросы. Следующее сообщение при ожидающем вопросе относится к нему; отдельная кнопка диагностики работает и в этот момент.
6. Отчёт и оригинальные JSON-свидетельства доступны справа. У каждого свидетельства есть scope и SHA-256. Исходники читаются только из зафиксированного Git commit, без clone/fetch и без изменения рабочей копии.

`/ask` явно отделяет консультацию от задачи; `/run` и `/cancel` — команды управления. Смена контекста запрашивает подтверждение `yes/да` или `no/нет`; сохраняет исходную задачу, архивирует старую область свидетельств, сохраняет израсходованный бюджет. Нельзя заменить контекст, пока не отвечен предыдущий вопрос.

## Проверки

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m ruff check performance_assistant tests
node --test tests/client-state.test.mjs
.\.venv\Scripts\python.exe -m performance_assistant schemas --check
```

Схемы обновляются командой `python -m performance_assistant schemas`. Для ограниченной среды можно указать pytest `--basetemp=data/test-tmp-UNIQUE` после создания `data`.

Реальный profiler deployment, поставщик модели и внешний executor в этой среде не предоставлены. Их совместимость необходимо подтвердить отдельным smoke-тестом; синтетические тесты не являются такой проверкой.
