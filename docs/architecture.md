# Архитектура и эксплуатация

## Ответственность

API валидирует команды, expected versions, request IDs и ставит задания в очередь. Никаких модельных/сетевых проверок в API-запросах нет. Worker получает задания с lease, выполняет один ограниченный шаг и атомарно сохраняет результат, события и завершение задания. Web и line TUI работают исключительно через HTTP. SQLite WAL находится на локальном диске, не на сетевой файловой системе.

`contracts.py` — versioned Pydantic-контракты; `service.py` — разрешения/жизненный цикл; `storage.py` — транзакции и fence; `worker.py` — обработчики; `workflow.py` — checkpointed investigation; `adapters.py` — MCP, Git и документ; `experts.py` — code-owned factories; `secrets.py` — vault; `conversation.py` — routing/extraction/consultation; `web/` и `tui.py` — клиенты.

Очередь использует at-least-once delivery. Read-only вызов может повториться после аварии между ответом сервера и локальным commit. Lease предотвращает повторный **commit**, но не обеспечивает exactly-once сетевые вызовы. Каждый шаг сохраняет план до выполнения, а ответы — до следующего планирования. Форматирование сохранённого отчёта не повторяет анализ. Внешний исполнитель обязан дедуплицировать operation IDs.

Состояния: queued → running → waiting → queued либо completed/failed/cancelled. У разговора максимум один активный run (в том числе waiting), что также защищено unique partial index. Неожиданные ошибки превращаются в безопасные reason codes. Истечение lease запрещает commit, включая ответы чата. Неподтверждённые результаты отбрасываются.

TaskPatch: отсутствующее поле не меняется; `null` очищает поле (summary → пусто, ref → HEAD, options → defaults, questions → []). Объект options заменяется целиком. `expected_version` обязателен. Незадачные сообщения не меняют ни значения TaskSpec, ни его версию. Извлечение получает текущую согласованную задачу и текущий запрос, а не историю советов.

## Ограничения

- Intake: 120 секунд общий deadline, общий консервативный byte-based input budget, 1800 выходных токенов и резерв 2048.
- MCP: 4 страницы, 128 инструментов, ответ до 1 MB, ограничение одного транспорта 20 секунд, без redirects/remote schema refs.
- Analysis: 8 вызовов, 8 чтений source, 3 planning rounds, 5 hotspots, отчёт до 32 KB, пользовательский активный бюджет 10–600 секунд.
- Diagnostics: срок актуальности 5 минут; отдельные подбюджеты источникам. Никаких фоновых внешних проверок.
- Lease: 150 секунд; waiting не расходует активный бюджет. После аварийного истечения lease начисляется консервативный полный lease, чтобы рестартами нельзя было обнулить лимит.
- Git: immutable commit, regular blobs 100644/100755, UTF-8, до 1 MB, без symlink/submodule traversal. Обязательные диапазоны задаются в `options.required_ranges` и сохраняются независимо от выбора модели.

## Хранение и версии

SQLite `user_version=1`; contracts `schema_version=1`, checkpoint `version=1`, report `report_version=1`. Неизвестная версия БД/чекпоинта не возобновляется. При будущих несовместимых изменениях необходима отдельная транзакционная миграция, архивирование исходных записей и тесты старого состояния; активный несовместимый workflow требует нового run. Автоматической миграции произвольных будущих версий нет.

Оригинальные ответы сохраняются отдельными evidence records, контрольный checkpoint содержит IDs, индексы и компактные планы. Известные credential values не допускаются в evidence, prompts, task commands, chat или события. Провайдерские ошибки наружу не выводятся. DPAPI на Windows связывает секреты с пользователем; `PA_MASTER_KEY` при явном задании переключает шифрование на Fernet. Не меняйте режим/ключ при наличии сохранённых секретов: сначала создайте безопасную резервную копию и заново введите токены. Sandbox может запрещать DPAPI — это явная ошибка, не повод сохранять открытый секрет.

## Восстановление

Закройте API/Worker перед файловой резервной копией. Копируйте всю папку `data`, включая WAL/SHM, либо используйте SQLite backup API. Секреты DPAPI переносимы только в рамках доступа исходного пользователя; Fernet требует сохранённый внешний ключ. После запуска Worker подберёт незавершённые задания после lease expiry. Не удаляйте lock-файлы и не меняйте статусы вручную.

Если run завершился `failed`, изучите безопасный code, доступные evidence и настройки; создайте новый запуск. Cancellation немедленно ограждает локальный commit. Уже отправленный read-only запрос может завершиться на сервере; внешний executor дополнительно получает `/cancel`.

Unauthenticated shared hosting не поддерживается: CLI жёстко использует loopback, API проверяет Host и Origin, принимает JSON для изменений и задаёт CSP. Не проксируйте приложение во внешнюю сеть без отдельного проекта аутентификации и авторизации.
